### GUI roadmap (after the 2026-11-19 rebuild, U-20261119-01)

The rebuilt window (sidebar, light / dark / system theme, layouts that adapt to the width) changed how the GUI looks, not what it can do. The items below are the gaps between the GUI and the CLI / MCP surfaces, plus improvements to what the GUI already does, in suggested order.

- **#20** No GUI view of the literature library. The SQLite library (`thesisagents/library/`) is reachable only through **Search library** on the Search page, while its runs, citation links, verdicts and statistics are CLI / MCP only (`library_stats`). Add a fifth sidebar page, **Library**: the statistics as a header (papers, runs, links), a filterable paper table, and for the selected paper its citation neighbours and stored identifier verdicts. Read-only first, so it cannot damage a library.
- **#23** The Deck page cannot check a template or audit a finished deck. A template that breaks the contract is reported only when the export starts. Add **Check template** (runs `exporters/template.py` validation, the same report as `thesisagents validate-template`) next to the template field, and a **Review a deck…** action that runs the `exporters/review.py` audit (overflow, colour contracts, `paper_rule` section completeness) on any `.pptx`, the same as `thesisagents review`.
- **#24** No PDF stage in the GUI: neither downloading the PDFs of the current results (MCP `download_pdfs`, CLI `--export pdf`) nor building a deck from local PDFs (`cli_local_pdf.py`, the CLI `--pdf` mode). Decision needed first: the IEEE / paywalled-publisher HARD rule (`CLAUDE.md`) requires asking about VPN access before any paywalled download and a visible Chrome window. Options: (a) a one-time question per session in a dialog, remembered until the app closes, or (b) a **Settings** switch "I have institutional / VPN access" that the download reads, with IEEE dropped from the PDF batch while it is off. Decided 2026-11-19 by the owner: (b).
- **#25** Changing the interface language needs a restart, because every page reads its labels once when it is built. Options: (a) rebuild the window in place and carry the state over (collection, form values, current page), little code but every page needs a state snapshot, or (b) a `retranslate()` per page that re-sets every label, the Qt-standard way, but each new label has to be added to it by hand and a forgotten one stays in the old language. Decided 2026-11-19 by the owner: (a).
- **#27** Enrichment without an API key has no GUI path. The Enrich page requires `ANTHROPIC_API_KEY` and otherwise only says so, while the project's main no-key flow is the LLM-as-agent path (an MCP-aware LLM authors the `PaperSummary`, `paper-summary-author`). Add an **Export for an agent** action that writes the collection as JSON with the PDF list, and an **Import summaries** action that reads the authored summaries back onto the collection, so the GUI can hand off to an agent and pick the result up.
- **#28** [UNVERIFIED] The rebuilt GUI has been checked by the test suite and by offscreen renders at 680, 1000 and 1400 px in both themes and both styles (classic, Material 3), not on a real screen. Open: how it looks and behaves at 100 / 125 / 150 / 200 % Windows scaling, with the OS switching between light and dark while the app is open, on macOS and Linux, and with a screen reader (every input needs an accessible name, the focus order should follow the cards). Check by running `thesisagents gui` on such setups and fix what does not hold.
