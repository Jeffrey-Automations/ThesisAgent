- **#11** A lightweight deck overflows its `meta` line when the paper title is long. Seen 2026-10-08 in the search smoke (`--query "transformer attention" --source arxiv --max 3`): `thesisagents review` reported `slide 3 / 4 / 5, shape "meta": overflows its box, rendered 0.6" vs 0.5"` for a 112-character title. The box is the title-plus-"Paper N of M" line in `_add_content_slide` (`thesisagents/exporters/pptx.py`), 0.5" tall at 15 pt with no shrink-to-fit, so a title that wraps to two lines does not fit. Not caused by the preflight work (`pptx.py` is unchanged there). Read `deck-design` and `slide-deck-rules` before changing the geometry.
- **#12** [UNVERIFIED] The `dblp` source returned a body that is not JSON. Seen once, 2026-10-08, in `--query "graph neural networks" --source arxiv,openalex,dblp,crossref,springer --max 5`: the new Sources table showed `dblp 0 returned  failed: [dblp] invalid JSON: Expecting value: line 1 column 1 (char 0)` while arXiv, OpenAlex and Crossref answered. Not known whether DBLP sent an error or rate-limit page (transient) or changed its response. Check what `thesisagents/sources/dblp/fetcher.py` receives (status code, content type) and whether a non-200 or an HTML body should map to `RateLimitError` / `SourceUnavailableError` instead of `ParseError`.
- **#15** A library keeps the first summary stored for a paper. `merge_papers` fills only empty fields, so a paper re-added with a better `PaperSummary` (a hand-authored rich one replacing an abstract-based one) keeps the old summary. Decide the rule (for example: a rich summary replaces a non-rich one) and add it next to `_with_latest_citations` in `thesisagents/library/store.py`.
- **#16** The research-question callout (`rq_box`) has a fixed height of 0.8 in, so a question that wraps to three lines overflows it. Seen 2026-10-08 while reviewing decks for U-20261008-07: an English `research_question` of about 170 characters gave `rq_box: overflows its box, rendered 0.95" vs 0.8"` from `scripts/check_overflow.py`, on the committed exporter as well, so it predates the template work. The stacked sections size their boxes from the estimated line count (`_stacked_body_height_in`), the callout in `_add_rq_callout` does not.
- **#18** [UNVERIFIED] Deck templates have only been exercised with templates derived from python-pptx's stock file (layouts renamed, a title placeholder moved, slide size changed), and the resulting decks were checked by the overflow inspector, the contrast audit and a python-pptx round trip, not by eye: this machine has neither PowerPoint nor LibreOffice. ### GUI roadmap (after the 2026-11-19 rebuild, U-20261119-01)

The rebuilt window (sidebar, light / dark / system theme, layouts that adapt to the width) changed how the GUI looks, not what it can do. The items below are the gaps between the GUI and the CLI / MCP surfaces, plus improvements to what the GUI already does, in suggested order.

- **#28** [UNVERIFIED] The rebuilt GUI has been checked by the test suite and by offscreen renders at 680, 1000 and 1400 px in both themes and both styles (classic, Material 3), not on a real screen. Open: how it looks and behaves at 100 / 125 / 150 / 200 % Windows scaling, with the OS switching between light and dark while the app is open, on macOS and Linux, and with a screen reader (every input needs an accessible name, the focus order should follow the cards). Check by running `thesisagents gui` on such setups and fix what does not hold.
- **#29** The GUI cannot build a deck from local PDFs. The CLI does (`--pdf FILE_OR_DIR`, `thesisagents/cli_local_pdf.py`: metadata from the PDF, then the normal export), but `build_from_local_pdf` takes the argparse `Namespace`, so a GUI caller would have to fake one. Split it into a function taking paths and options, then add **Add local PDFs…** to the Search page that fills the results table from it. Left out of #24 (done 2026-11-19, U-20261119-06), which covered downloading the PDFs of a result.
- **#31** The GUI cannot tell whether a paywalled PDF went through Chrome. `core/pdf_download.py` (lines 140-148) sends a paywalled URL to plain httpx without a log line when `webrunner_pdf.is_available()` is false (selenium missing, or the disable variable set), and falls back to httpx with only an INFO log when the browser download fails. The CLI shows that log, the GUI does not, and the `CLAUDE.md` rule says a missing Chrome window must be surfaced. Add the path each PDF took (browser / direct / skipped and why) to `PdfDownloadResult`, and show the browser-unavailable case on the Deck status line. Found by the compliance read of U-20261119-06. Read `compliance-auditor` before changing `core/pdf_download.py`.
